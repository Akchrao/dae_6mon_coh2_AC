2.4 Incident triage and prioritization: three incident types

Incident (IR1)TypeImpactUrgencySeverityBusiness impact
IR1-2026-002Unauthorized ePHI access by a mover (old clinical group kept), record sent off the host33SEV-1 (9)HIPAA breach risk assessment, patient notification possible, regulator reporting
IR1-2026-003Unapproved privilege: a joiner given sudo without a change record, used root32SEV-2 (6)System integrity in doubt; audit finding; possible persistence
IR1-2026-001Leaver login attempts (blocked, but SSH key still on the host)22SEV-3 (4)No access gained; control weakness to fix

Severity = Impact × Urgency (each 1-3), NIST SP 800-61 prioritization factors; SEV-1 start within 15 min, SEV-2 60 min, SEV-3 8 h. Today's CB2 cases were rated SEV-2 (server access gained, no ePHI confirmed read).

2.5 Post-incident analysis

CaseOutcomeLessons learned
IR1-2026-002 (SEV-1)Contained by isolating the VM; recovered from the baseline snapshot; validation 34/34 checks and 6/6 network probes, before and after reboot1. A mover's old groups must be removed before new access is added (JML control fixed by recover_harden.sh). 2. Leavers need their SSH keys removed, not only their account disabled.
CB2-2026-001 (SEV-2)Closed: account locked, SSH keys only, re-test refused the password; response 5.9 min (target 60)3. Password-only SSH is guessed within seconds: keys only on all servers (PROC-SEC-03). 4. Containment waited 21 h because the compromise was kept for the Security Monitoring 1 evidence; in production containment must start within the SLA.
CB2-2026-002 (SEV-2)Closed: staged copy preserved and removed, deleted export restored, hash matches known-good5. Egress allow-lists on servers would have blocked the outbound connection (100630). 6. Keep FIM on every ePHI folder: it was the only record of the staging.
